# Security Policy

## Supported Versions

We take security seriously across all KRInnov projects. Security updates are provided for:

| Project Type | Supported          |
| ------------ | ------------------ |
| Active projects | ✅ Latest version |
| Maintained projects | ✅ Latest version |
| Archived projects | ❌ No updates |

## Reporting a Vulnerability

We appreciate responsible disclosure of security vulnerabilities. Please follow these steps:

### 🔒 Private Reporting
1. **DO NOT** create a public GitHub issue for security vulnerabilities
2. **DO** contact us privately through one of these methods:
   - GitHub Security Advisories (preferred)
   - Email repository maintainers directly
   - Use private vulnerability reporting features when available

### 📋 Information to Include
- Description of the vulnerability
- Steps to reproduce the issue
- Potential impact assessment
- Suggested fix (if you have one)
- Your contact information

### ⏱️ Response Timeline
- **Acknowledgment**: Within 48 hours
- **Initial Assessment**: Within 5 business days
- **Status Update**: Weekly until resolved
- **Resolution**: Timeline depends on severity and complexity

### 🎯 Severity Guidelines
- **Critical**: Immediate attention, patch within 24-48 hours
- **High**: Priority fix, patch within 1 week
- **Medium**: Standard timeline, patch within 2-4 weeks
- **Low**: Include in next regular release

## Security Best Practices

### For Contributors
- Use secure coding practices
- Keep dependencies updated
- Follow principle of least privilege
- Validate all inputs
- Use secure communication channels

### For Users
- Keep software updated
- Use strong authentication
- Follow repository security advisories
- Report suspicious activity

## Recognition

We appreciate security researchers who help us maintain secure projects:
- Public acknowledgment (with permission)
- Credit in security advisories
- Hall of fame recognition (for significant findings)
